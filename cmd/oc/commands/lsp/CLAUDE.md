# Notes on `orgs lsp`

Loaded when working in this directory. References like **Traps: line edits** point at the Traps list in the root `CLAUDE.md`. User guide: `docs/lsp.org`.

A language server over stdio, and a **client** of `orgs serve` like `orgs mcp`. In-file features (symbols, folding, completion of this file's headings and keywords, links within the file, structural diagnostics) are worked out here from the buffer with go-org, configured as the server's `GetConfig` with the server's keywords from `/status`. Cross-file features are one request each. With no server the in-file features still work (`NeedsNoServer`).

Files: `rpc.go` transport, `protocol.go` types, `text.go` documents/positions/diffs/paths, `org.go` headings (from go-org's outline), blocks, drawers, links, symbols, folding, `complete.go`, `links.go` (definition, document links, workspace symbols), `diagnose.go`, `actions.go` (code actions, lens, commands, refile/archive sync), `api.go` (every server call).

- **Transport**: Content-Length framing. The server also *asks* the client (`workspace/applyEdit`, `window/showMessageRequest`), so the reader loop hands responses to waiting `conn.call`s, notifications are handled **in order on the reader** (a request after an edit sees the edit), requests run on goroutines, and `initialize` runs on the reader so the position encoding is settled before any didOpen.
- **`os.Stdout` is pointed at stderr in `Exec`**; the protocol writes to the original. go-org prints a recovered parse panic's stack with `fmt.Println` (document.go), and any unclosed `#+BEGIN_SRC` - every block while it is being typed - panics in `parseLineBreak`; on stdout that is a broken message and VS Code's client stops the server, silently (found through vscode-org-everywhere's test).
- **Editors that log in themselves** (vscode-org-everywhere) hand the token in `initializationOptions.token` and renew it with `workspace/didChangeConfiguration {settings: {token}}`; the server then never renews or persists one itself. `orgs lsp` runs with no config file (`ParseConfig` lets it, as `help`), `-url` saying where.
- **Positions**: `utf-8` when the client offers it, else `utf-16`. Everything inside is byte columns; convert only at the edge (`enc.pos`, `enc.byteAt`).
- **The buffer is the truth.** Schedule/deadline/run post the buffer to **`/lsp/date`** and **`/lsp/run`** (`internal/app/orgs/textedit.go`), which run the file endpoints' own line edits (`changeDateLines`, `runItemLines`) on the given text and answer with text; `enc.diffEdit` turns that into one versioned edit. A run answered after the person typed more is refused by the client's version check rather than misapplied.
- **Refile/archive work on files**, so they refuse a buffer that differs from the file (`disk`: here, else `/orgfile`). The heading's hash is computed **here** by parsing the buffer under the server's path (`remote`) - same parser, same text, same hash (see **Traps: hashes**) - and checked with `/hash/{h}` (line must match), which also catches a server that has not read the save yet. Then `/move`. `catchUp` waits 800ms for the editor to reload files it had saved, and edits the buffers still behind (Helix, Vim without autoread would otherwise save the old text back over the move).
- **Run is offered only where it would run**: `/lsp/runnable?lang=` (babel on, a runner, in `babel.languages`); otherwise a disabled action with the reason when the client supports it.
- **Diagnostics are thrown away when the buffer changed while they ran**, and kept per version (`diagFor`) so quick fixes come from what was published, not from what the client echoes back.
- **The token is renewed every 20 minutes** through `core.Refresh` (set in `main.go`; minted local tokens are re-minted), under `api.mu`'s write lock since it rewrites the shared header. `getCached` remembers failures too, so a down server costs one timeout a minute, not one a keystroke.
- **Lint** is `lint.Checkers`/`lint.Check` (exported for this; the command's flag handling stays in `lint.go`). `found.end` / `para.placeEnd` give a lint its extent.

Tested by `lsp_test.go` through pipes and an `httptest` server; by hand with a Python driver against `orgs -orgdir DIR lsp`.
- **Structural diagnostics, blocks, drawers, links, headings and the in-file search are `internal/common/orgcheck`**, shared with the server's `POST /lsp/diagnose` (worg's editor). Change the rules there; `lspEnv` here and `serverCheckEnv` in the server only answer files, ids and features.
