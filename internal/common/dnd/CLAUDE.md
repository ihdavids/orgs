# Notes on the D&D module

Loaded when working in this directory. References like **Traps: line edits** point at the Traps list in the root `CLAUDE.md`.

## The D&D module

- `internal/common/dnd/` — engine shared by server and CLI (must not import `internal/app/orgs`):
  - `types.go` model; `ruleset.go` load/merge yaml modules; `rules.go` `Character` → `Sheet`; `builder.go` creation state machine; `orgfile.go` org sheet read/write; `view.go` sheet → template map.
  - `inventory.go` stacks equipment into containers, applies changes; `money.go` purse and paying (incl. change); `shop.go` buy/sell in one call; `consume.go` applies what using an item does, read from its text.
  - `spellcast.go` what a cast rolls; `slots.go` spend/return slots; `spellbook.go` learnable/preparable spells within class allowances; `concentration.go` held spell and the Con save a blow costs.
  - `uses.go` per-rest limits from feature text or a ruleset `usesByLevel` column; `rest.go` what a short/long rest costs and returns.
  - `conditions.go` condition catalog and defenses (`DefendDamage`: resistance/immunity/vulnerability on one blow); `rolleffects.go` conditions' effect on d20s (advantage, disadvantage, auto-failed saves) as a lookup map for the sheet; `health.go` damage, healing, temp HP, `HealthLevel` (HP bar band); `inspiration.go`.
  - `undo.go` reverses the last operation from the logs (item plus the HP/coin that moved); `fuzzy.go` matcher shared with the CLI chooser; `ddbeyond.go` D&D Beyond payload → `Character` by matching names to ruleset ids; `portrait.go` fallback portrait; `backdrop.go` scenery behind the html sheet - pictures from `DND_BACKDROP` (a folder means all in it), display time and strength.
  - `levelup.go` — behind `orgs dnd levelup` and `POST /dnd/levelup` (`internal/app/orgs/dndlevelup.go`); emits the builder's `Prompt` type, so the CLI chooser and the sheet's level-up tray render it unchanged.
- `internal/common/dnd/data/*.yaml` — SRD ruleset, `go:embed`ed. **Generated**, do not hand edit: `python3 tools/dndsrd/gen_srd.py ../dndsrd` (the [dndsrd](https://github.com/OldManUmby/DND.SRD.Wiki) markdown SRD).
- `internal/common/dnd/data/portraits/*.svg` — embedded per-race fallback when no `DND_IMAGE`: SRD races plus aarakocra, tabaxi, aasimar, firbolg, triton, goliath, warforged, yuan-ti, cairnborn, each drawn to its race entry (tabaxi: cat ears, muzzle, slit pupils), not a recoloured human. **Generated**: `python3 tools/dndportraits/gen_portraits.py`; do not edit the svg.
- Sheet side drawers: dice tray (auto-open: every roll / not on casts / never - casts roll hit and damage at once and get tiresome), level-up tray, session drawer (Notes, Timeline, Combat, Sessions, Inventory, Search).
- `internal/app/orgs/dnd.go` — `/dnd/*` endpoints and build session store; plus `dndsession.go` (play logs), `dndinventory.go`, `dndspells.go`, `dndmoney.go`, `dndrest.go` (rests, feature uses), `dndconditions.go` (conditions, defenses), `dndhealth.go` (HP, death saves), `dndconcentration.go`, `dndinspiration.go`, `dndundo.go` (sheet menu undo) - all rewrite the character's org file - and `dndimport.go` (D&D Beyond import; the CLI fetches, so no D&D Beyond credential reaches the server). `internal/app/orgs/plugs/dnd/`: shared ruleset library, `dndsheet`/`dndlatex`/`dndpdf` exporters.
- `cmd/oc/commands/dnd/` — `orgs dnd`; `templates/dnd_character*.tpl` — html and latex sheets.

Rules:

1. **The builder replays all stored answers onto a fresh character** on any change: `apply` must be deterministic; randomness (dice) is stored on the `Answer` (`Answer.Pool`).
2. **Only the property drawer and the equipment, spell, inventory/coin/condition/health history tables are parsed back**; `RenderOrg` regenerates the rest, so derived data must never be the only copy. `*** Defenses` under Combat is regenerated from `DND_CONDITIONS` / `DND_RESISTANCES` etc.; editing it does nothing.
3. **House rule**: a short rest returns one slot of each level spent (SRD: warlocks only). `ApplyRest`/`RestPlan` in `rest.go`; `TestShortRestGivesBackOneSlotOfEachLevel`.
4. `HealthLevel` ↔ `hpLevel` (see **Traps: logic said twice**); the JS copy lets a rest recolour the bar without a round trip.
5. **`uses.go` parses prose, best effort**: unstated limits are never guessed. Rage, ki, sorcery points (sized in class tables) carry `usesByLevel` from `USES_FEATURES` in `tools/dndsrd/gen_srd.py`; a declared column/formula beats prose. `rest_test.go` pins wordings and columns; add a case before loosening a pattern.
6. **`LevelUp` (`levelup.go`) returns a levelled copy**, never mutates: the flow is stateless (client resends all answers, engine replays), so in-place would re-add levels each pass. `classLevelOf` returns the *whole* level when the class is absent (right for building, wrong for multiclassing); `classLevelIn` is strict.
7. **Merging is not uniform**: existing ids under `races:`/`classes:` merge field by field; under `spells:`/`items:`/`backgrounds:`/`feats:` they **replace**. Never restate an SRD spell to change a field (forks generated data, goes stale); give a spell to another class with `spellLists: {druid: [...]}`, appended at index time and accumulating across modules (`spelllists_test.go`).
8. **Item use (`consume.go`) and value (`shop.go`) come from the ruleset, never the page**: the sheet gets `use`, `price`, `sale` per inventory entry and posts back dice results. Best effort like `uses.go`: healing *every hour* or *while worn* is not a dose. `TestItemUseFromSRD` pins the three SRD items with one; a new hit is a change to review.
9. **Conditions reach dice only via `rolleffects.go`.** The page gets a `RollAdviceView` (owed per roll kind, saves keyed by ability) and never learns what "poisoned" means, so a new condition is a `conditionRules` row with no sheet change. Advantage and disadvantage **cancel**, not count. Nothing is forced: all three readings are rolled and only which stands changes, because caveats ("while the source of your fear is in sight") are the table's call. Every template rollable needs `data-roll-as` (and `data-ability` where relevant) or is owed nothing.
10. **History undo (`undo.go`, `/dnd/undo`) reverses only the true last operation**, from history tables, not server state - hence the `Was` column in Health and Coin History: the prior state cannot be derived and undo never guesses. Lines from sheets predating those columns are refused (not read as zero). The character must still be exactly where the line left them; otherwise something (blow, rest, hand edit) happened since.
11. **Sheet palette** (`/` or ctrl-k) indexes the page's own controls (`.rollable[data-label]`, `.cast-btn`, usable inventory rows, `.feature[data-uses]`), so it cannot go stale and finds new controls. Matcher: `FuzzyScore`/`FuzzyScoreAll` in JS (see **Traps: logic said twice**) - a round trip per keystroke defeats a palette.
12. **A spell's look is decided only in the sheet's `ELEMENTS` table.** Order: spell **name** (`SPELL_ELEMENTS` - water, earth, healing, holding, missiles, bangs are never labelled by the rules), then **damage type**, then the magic circle, so every cast shows something. `variants` + `pickLook` pick one per cast. Traps: the elemental layer uses `projectUp`, a *leaned* camera, since the top-down dice camera flattens upright things to nothing; effects time from the frame's `now`, not the wall clock, or expire on frame one.
13. **`SPELL_ELEMENTS`: first matching regex wins**, so order is meaning. Storms and hands go near the top: sleet storm does no damage and would fall to the circle; "Bigby's grasping hand" would hit the binding regex's `grasp\w*`. Weapons usually arrive with a damage type and skip the list.
14. **Skill flourishes**: `SKILL_ELEMENTS` maps a `.rollable` label to an element; `specFor` adds it like a damage type. Only skills with an obvious picture (no Athletics); others get dice only, keeping flourishes special. The magnifying glass breaks on low and sparkles on high, so the natural d20 goes to `throwDice` as `opts.quality`, kept by the board.
15. **Merged silhouettes (only the ghost hand so far) are filled, never stroked**: `ctx.stroke()` outlines every subpath, drawing the palm across the fingers. The rim is a slightly larger under-fill. Nails, knuckle wrinkles, tendons, veins, web notches and a lit side together make it a hand, not a cartoon.
16. **Upright reader-facing flats (shield, book, hand, cat) use `DiceBoard.prototype.billboard`.** Not a basis from three projected points: they sit at different heights, `projectUp` scales by height, and the frame shears (a shield became a parallelogram on the table).
17. **Replacing a template block by index: anchor both ends.** Flourish routines run newest-first, so `s.index(endBanner)` without a start offset can hit an *earlier* banner; `s[:a] + new + s[b:]` with `b < a` duplicates the span, the stale later copy silently wins, and edits stop taking effect. Happened twice; `TestNoDuplicateFlourishRoutines`.
18. **Five flourishes are meshes**: cairn stones, panther, mage hand, shield, shared rocks. `meshBuilder().tube()` rings each path node and stitches rings into quads (animal: nine calls, hand: seven); `rockMesh` deforms an icosahedron. `DiceBoard.prototype.drawMesh` transforms, projects, culls back-faces, sorts far-to-near, flat-shades by face normal - no gradients, hence low poly. Modes: `solid` (stone), `wire` (conjured: faint fill hides the far side, light in edges and vertex nodes). Traps:
    - z-as-up meshes are seen from directly above and read as columns; side-view objects are pitched a quarter turn;
    - the shield is a dished plate, face and rim wound oppositely: request `twoSided` (no culling), and the dish must be **positive** or it faces into the paper;
    - `tube()` guesses ring frames from travel; along z it swaps the radii's axes, so non-round sections (palm ~3:1) pass `upHint` or lie on edge;
    - caps are one polygon, not a fan - the wire glow pass turns fan slivers into spikes;
    - pose changes rebuild the mesh, so the panther quantises leg swing to twelve poses.
19. **Flourish drawing**:
    - **The page is cream**: `lighter` alone washes out. Bright effects need a dark normal-blend pass first (`drawStrike` lays a dark bruise before its four light passes; sparks, motes, embers glow with `lighter` and have a saturated core without it). So the strike's `flash` **darkens and cools**, and as a full-screen brightness change is skipped under `FLASH_OFF` (read once from `prefers-reduced-motion`).
    - **Sound**: `ELEM_VOICE` keyed on the look's `kind`, not the element; no entry = silent (right for an undesigned noise, e.g. a module's cold spell gets ice and no sound). Voices pick variants per cast with `pickOne` (like `pickLook`); `bind` gets the look's `lay` instead of a loudness, so hemp, chain and vine differ.
20. **Undo has two mechanisms, tried in order.** `dndjournal.go`: in-memory copies of the last thirty changed files, hooked into the write choke points `dndWriteCharacter` and `updateDndSession`; an entry is valid only while the file is unchanged since (else restoring would lose later work) and is dropped otherwise. It covers changes that write no history, and session files too. Memory only on purpose: a convenience for recent play, not a record. Fallback: `undo.go` from history tables, which survives restarts and handles files changed elsewhere.
21. **Deleting is not doing.** `InventoryDelete`, `DeleteNote`, `DeleteRoll` remove a line and write **no** history: they correct the record (stray click, unwanted note), not record an event. Dropping, using, selling do log. Note/roll deletes take a `was` (note stamp, roll label) and refuse on mismatch, since deletion shifts later entries and a stale page would delete the wrong one.
22. **Notes keep typed line breaks**: org flows prose together, so `orgBreakLines` (`sessionlog.go`) writes `\\` where lines would join and `orgStripBreaks` removes only those on read, for an exact round trip. The sheet's `orgToHtml` matches (see **Traps: logic said twice**).
23. **Session drawer panes scroll individually** (`.nd-view { overflow-y: auto }`): fixed-height drawer, long timelines and fights. Except notes: a two-column split whose halves scroll themselves (two bars would conflict).
    - **Timeline** is derived from the session's two logs, never written back: rolls closer than `TL_GAP` minutes, at least `TL_LEAST` of them, form a Combat block; notes inside hang off it; `TL_SCENE` minutes of quiet is a scene break. Sessions edited elsewhere are right on next open.
    - **Combat** tracks the table, not the character: initiative, rounds, turns, enemy HP, and two countdowns - a combatant effect ticks at the start of *their* turn ("until the end of your next turn"), a table clock at the top of each round. Lives in `localStorage`, no endpoint: goblins do not belong in the character file.
24. **Concentration is stored** (`DND_CONCENTRATION`), like conditions. `/dnd/hp` returns the DC as `save` (10 or half the damage, counting temp-HP-soaked damage); the sheet rolls and posts to `/dnd/concentration`. Zero HP ends it with no save; so does a long rest.
25. **Timeline annotations are the only stored part** (`sessionmark.go`, a `* Timeline` section in the session file). Nothing else about a block (roll count, duration) may be stored beside one, or it goes stale on a corrected roll. Anchor = **time and kind together**, so a name for the 19:32 fight never reattaches to a note at that minute. Unmatched marks become their own beat, not dropped: names survive deleted blocks, and the toolbar's *Annotate* adds unrolled moments (kind `moment`, which no block has).
26. **Deleting a timeline block is one call** (`POST /dnd/play/session/{id}/delete`) with all its rolls and notes: one write, one journal entry, **one undo**. Any refusal refuses all (half a deleted fight is worse). `DeleteEntries` removes back to front so shifts never hit an unused index.
27. **The timeline's own undo** (`/dnd/play/session/{id}/undo`) is the journal narrowed to one file (`dndLastChangeTo`): the sheet's Undo is global, but the drawer must undo *that evening*, or delete-block-then-roll would offer to un-roll the die. Only a file's newest entry is offered, making mid-journal removal safe.
28. **Folding and timeline search are page-only**, written nowhere (reading, not events).
    - A card folds by **its spine dot** (`tlDot`), not a chevron among the tools: the eye scans the dots, and the right-hand tools are the two that change the session file (name, delete), so a view-only button there read as one of them.
    - *Fold all* clears per-card overrides (an old open card staying open is not what it says).
    - Search matches **everything a card holds** (`tlHay`), not what is shown, or folding hides the spell being searched for.
    - Direction (`TL.dir`: down / up / across, `#tl-dir`, kept in `localStorage`) only changes drawing: events and gaps are built in time order and reversed for *up* (hits too, so Enter still steps down the page). *Across* draws the spine per column, since a line on a scrolling box spans only its visible part.
