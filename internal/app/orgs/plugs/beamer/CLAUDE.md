# Notes on the beamer exporter (`plugs/beamer`)

Loaded when working in this directory. References like **Traps: pointer trap** point at the Traps list in the root `CLAUDE.md`.

An org file as a LaTeX Beamer deck, following ox-beamer so a deck written for Emacs exports the same. The SDOC in `beamer.go` is the user guide. `beamer.go` (exporter, preamble, presets), `writer.go` (the outline walk and every node), `compile.go` (tex to pdf), `beamer_test.go`. The pdf endpoint `GET /beamer/pdf` and `GET /beamer/themes` are `internal/app/orgs/beamerpdf.go`. `Standalone()`, so it needs no yaml.

- **Its own writer, not the latex exporter's.** That one renders through pongo2 templates per document class and carries the D&D book's headings; a deck needs to decide where frames, columns and blocks open and close, which a heading written one at a time cannot. The outline is walked from `WriteHeadline` with the frame level in hand; inline nodes go through `org.Writer` as usual.
- **The frame level is org's**: `H:` from the file, then the exporter's `frameLevel`, then **1** (ox-beamer's default, not 2). `option()` reads `#+OPTIONS:` without `GetOption`, which logs a complaint for every option a file does not set.
- **go-org upper-cases property names** (`:BEAMER_env:` is `BEAMER_ENV`) and `PropertyDrawer.Get` is case sensitive: read them with `prop()`, which ignores case. The B_env tag is the fallback, as org has it.
- **`fragile` is found out by writing the frame's body first** (`frameOf` into a fresh buffer; `code`/`WriteExample` set `w.fragile`), then the `\begin{frame}` line is written. `\end{frame}` must be on its own line, and is.
- **`#+ATTR_BEAMER:` is not an affiliated keyword to go-org**: it arrives as a keyword node and lands in `BufferSettings` too. `WriteKeyword` keeps it for the next list/block (`attrBeamer`). `#+ATTR_LATEX:`/`#+CAPTION:` come on `NodeWithMeta` as usual.
- **Item overlays (`- <2-> point`) are matched in the written item**, where `<`/`>` are already `\textless{}`/`\textgreater{}` (`escape` escapes them, so T1 is not needed for them to print).
- **listings and anything not ascii**: listings reads bytes, so `ü` or `—` in a block stopped pdflatex ("Invalid UTF-8 byte sequence"). `listingText` hands each such run back to latex through `escapeinside={(*@}{@*)}`. The extra languages listings lacks (or got only lately: Go) are defined as `orgsGo`, `orgsJavaScript`... - a definition named `Go` met TeX Live's own lstlang3 one and lost its keywords.
- **Pictures are absolute paths** (resolved against the org file), so the deck compiles in a temp dir; an `.svg` with a `.pdf` beside it uses the pdf.
- **Presets** (`clean`, `dark`, `metropolis`, `classic`, `academic`, `minimal`) are preambles in `presets`; clean and dark share `cleanBase` and differ by five `\definecolor`s. `metropolis` falls back to clean when `kpsewhich` cannot find it (answer cached). Theme precedence: request `theme` > file `#+BEAMER_THEME:` > exporter `theme` > metropolis/clean. A name that is not a preset is a beamer theme's (`\usetheme{Warsaw}`).
- **Compile** runs the engine twice (outline, labels, frame counts), `latexmk` once; `-shell-escape` only for minted. Engine: exporter `latex`, then the `pdf` exporter's `pdfLatex`, then pdflatex/xelatex/lualatex on PATH or in `/Library/TeX/texbin` (launchd has no TeX on PATH). The error returned is latex's first error line onward (`-file-line-error` form included).
- Look at a deck: `ORGS_BEAMER_ORG=deck.org ORGS_BEAMER_PDF=/tmp/deck.pdf [ORGS_BEAMER_THEME=dark] [ORGS_BEAMER_ENGINE=xelatex] go test -run TestCompileSample ./internal/app/orgs/plugs/beamer/` writes the pdf and the tex beside it.
