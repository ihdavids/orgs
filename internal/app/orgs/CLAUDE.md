

## More optional packages, second set: map, timeline, library, hover previews, link titles, maths typing, local pictures

Seven more `features:` switches, built like the first set (guide: `docs/note-packages.org`). CLI commands in `cmd/oc/commands/orgpkgs/` (`mapview.go`, `timeline.go`, `library.go`, `peek.go`, `linktitle.go`, `latex.go`, `images.go`). Outside services (Nominatim, OSM tiles, Open Library, Wikidata, MusicBrainz, TMDB/IGDB/RAWG with keys, any web page for titles and pictures) are fetched http(s) only, with timeouts, size caps and private addresses refused unless allowed, and never in tests.

### Map view: `mapview.go`, `mapgeocode.go`, `mapstatic.go` (features.mapView, org-osm)

Pure half `internal/common/geo` (`geo.go`: `Parse`/`Format`/`OSMUrl`, web mercator `WorldPx`/`FromWorldPx`/`FitView`, `PinColour`/`HashIndex`; `place.go`: wire type `Place`, `PlacesAnswer`, `GeoJSON`), pinned by `geo_test.go` over `testdata/geo_cases.json`. Server: `mapview.go` (`registerMapRoutes`; `GET /map/places`, `POST /map/geocode`, `POST /map/set`, `GET /map/status`), `mapgeocode.go` (settings accessors, the geocoder, its cache and queue), `mapstatic.go` (`GET /map/static`, tiles, the SVG, the `#+MAP:` export pass). Tests `mapview_test.go` (a fake Nominatim on httptest - never the network). Settings `common.MapViewSettings` (`mapView: geocodeUrl, email, autoGeocode, geoProperty, tileUrl, tileDarkUrl, attribution, staticTiles`). CLI `orgs map` (`cmd/oc/commands/orgpkgs/mapview.go`). User guide: "Places on a map" in the more optional packages guide (`docs/note-packages.org`).

- **A place is org's own `:LOCATION:`** (what ox-icalendar writes into LOCATION). Read by `mapPlacesOf`, one `geo.Place` per place: `LOCATION` (coordinates → `How: coordinates`; a url with none is skipped, not geocoded; words → an address), `LATITUDE`+`LONGITUDE` (`latlon`), every `ADDRESS`/`ADDRESS_<label>` (records' vcard fields; `Label` = lower-cased suffix), and a bare `:GEO:` when nothing else. Properties are read case-insensitively off `sectionProps` (go-org keeps their case; `GetProp` is case-sensitive).
- **`:GEO:` belongs to the heading's main place** (the first: LOCATION, else the first ADDRESS_*) and wins over the cache for it (`How: geo`). `/map/set` takes it off whenever it writes LOCATION, unless it writes a new one in the same `reviewWrite` (a stale GEO would put the pin at the old address). Written as `geo.Format`: `lat,lon`, up to 6 decimals, no trailing zeros - plain words Emacs users can read and paste into any map.
- **Writes are `reviewWrite`** (orgreview.go): drawer made where org keeps it, column-zero files stay column zero, `alignDrawer` realigns the drawer (so a write can re-space the drawer's other lines - org's own `org-property-action` does the same).
- **`parseCoords` rules** (`geo.Parse`): plain `lat, lon` (comma, semicolon or space; optional parens), `geo:` uri, exactly two hemisphere-marked DMS/decimal parts and nothing else (`Flat 4N, 12 Main St` stays an address), urls: `mlat/mlon`, Google's `!3d..!4d..` (the dropped pin) before `q/query/ll/sll/center/destination/daddr/cp/coord` (Bing's `~`), then `/@lat,lon`, then OSM's `#map=z/lat/lon`. `0,0` is "never set", not a place.
- **Geocoder** (`mapGeocoder`): `mapView.geocodeUrl` (Nominatim's `/search` by default, any compatible one), `format=jsonv2`, `email=` when set, User-Agent `orgs/<version> (...)`, 12s timeout, 1 MB cap, **one request at a time `mapGeoGap` (1s) apart** under `reqMu`. Cache `<config>_geocode.json` beside the yaml (user cache dir without a config), keyed by lower-cased, space-collapsed address; misses are kept as `missing` (the cache answers "not found" without asking again; `/map/geocode {Hash}` forces a new ask). **A network failure is not kept.** Saved on every put (temp + rename, 0600).
- **Nothing is looked up unasked** unless `autoGeocode`: `/map/places` only counts `Unplaced`. `{All: true}` queues unknown addresses (`enqueue` dedups against cache and queue) for one goroutine (`work`), which stops on an empty queue, the feature turned off, or the first network error (the rest stay unplaced). It publishes **`map` events** (`EventMap`, after every 5 placed and at the end); `/map/set` and `/map/geocode {Hash}` publish one too. worg listens to `reload,map` and also polls every 2.5s while `Pending > 0`.
- **`/map/geocode {Address}`** answers up to `Limit` hits (search for "place this heading") and caches the first under that address; coordinates typed there answer themselves with no request. `/map/set` with `Lat/Lon` (a picked result) caches the address → those coordinates, so the pin shows before any lookup.
- **Queries**: `mapPlaces(query, file, colour)` - `queryEachSection` for a query, else a walk of the file or of every file (`registerAllSections` first: **Traps: hashes**, sections register lazily). Snippet = `mapSnippet`: own lines, drawers/planning/keywords/blocks out, links as their descriptions, 200 runes.
- **Static picture** (`mapSvg`): view from `#+MAP:` center/zoom or `geo.FitView` (pad 36, max zoom 17; one point = 15). Tiles: `mapView.tileUrl` (`{z}/{x}/{y}`, `{s}` → `a`), cached a month in `<user cache>/orgs/map-tiles/<sha1(url)[:10]>/z/x/y`, a stale tile used when the server cannot be reached, two fetches at a time, **at most 30 tiles a picture** (more = no tiles), and after one failure the tile server is considered down for 5 minutes (so a page of maps offline does not wait 12s per tile). Composed into one JPEG (q80, ~40-120 KB, base64 in an `<image>`), pins as vector teardrops numbered 1..n (no numbers past 40) linking to openstreetmap.org, drawn north to south, wrapped across the antimeridian; attribution bottom right linking to `/copyright`. No tiles: a pale ground with a graticule labelled in degrees. Every pin `<a>` carries `data-hash/-file/-line`.
- **Export pass** (`mapExportLines`, last in `exportLinesFor`, flag `mv` = `mapMayApply`: feature on and `#+map:` in the text): html-ish backends (`trackerBackendKind`) get `#+BEGIN_EXPORT html` with `<figure class="org-map" data-map-options data-map-file data-map-height [data-map-from data-map-to]>` + svg + a numbered `<ol>` of the places (left-aligned explicitly - themes centre figcaptions); every other backend a numbered org list `1. [[osm-url][Title]]: lat,lon` (a ` - ` there was read as a nested list by the ascii exporter). Lines inside `#+begin_` blocks are skipped. An unreadable line becomes `/Map: why/` + a stderr line.
- **A `#+MAP:` with no query shows the subtree it is under** (above the first heading: the file). The copy's rows are not the file's (the tracker pass turns one line into three), so `mapSubtreeOf` finds the heading again in the file on disk by its outline path (the headline lines of each level above it) and filters places by the file's rows; those rows go out as `data-map-from/to` so worg's live map shows the same set. `TestMapExport` pins a shifted copy.
- `GET /map/static?ll=lat,lon&title=` draws one pin (VS Code's hover); `format=json` answers `{Ok, Svg}` because the extension's request helper only reads json.
- Name clashes avoided (several agents in one package): everything package-level is `map…`-prefixed (`mapGeocoder`, `mapGeoKey`, `mapSpacesRe`, `MapGeoHit`, `mapGeoEntry`, `mapGeocodeCachePath`, `mapDefault…`).
- Seen working against a throwaway server (8121) with real Nominatim and OSM tiles: `orgs map`, `geocode -all` (two found, one not), `set` with `-geo`, `geocode -hash … -write` into a record's drawer, `open -json`, `-format geojson`; the html export looked at in headless Chrome (tiles, numbered pins, list).

Not done: a `HasLocation()` query function; inherited `:LOCATION:` (org does not inherit it by default either); routes/distances; a heatmap layer; spiderfying identical coordinates (clusters at zoom ≥ 18 are drawn as separate pins on top of each other); LaTeX/Typst get the list, not the picture (the JPEG could be written beside the file as the excalidraw pass does); the subtree export view (`subtreeViewFor`) has no map pass.

Twins (for the root list):
- **coordinates and pin colours**: `geo.Parse`/`Format`/`PinColour`/`HashIndex` (`internal/common/geo/geo.go`) ↔ `parseCoords`/`formatCoords`/`pinColour`/`hashIndex` in `worg/src/mapview.ts` ↔ `parseCoords`/`formatCoords` in `vscode-org-everywhere/src/map-model.ts`. Same cases: `internal/common/geo/testdata/geo_cases.json`, copied to `worg/src/mapview_cases.json` and `vscode-org-everywhere/test/fixtures/geo_cases.json` (`TestGeoCases`, `mapview.test.ts`, `test/map-model.test.ts`) - copy the file when a case changes. `HashIndex` is UTF-16 units × 31 with 32-bit wrap, absolute value (INT_MIN → 0) mod n. Drift shows as a typed location being searched for instead of placed, or the exported picture's pins in other colours than worg's.
- The `#+MAP:` words are read by `common.ParseTrackerOptions` and, in worg, `parseTrackerLine`/`trackerLine` (tracker.ts) - already a twin; `parseMapLine`/`mapLine` in mapview.ts only name the keys.

Shared files touched (small): `rest.go` (one route line), `refresh.go` (the `mv` flag and pass in `exportLinesFor`), `common/serversettings.go` (`MapView` + SDOC block, `MapViewSettings`).

### Timelines: `timeline.go`, `timelinesvg.go` (feature `timeline`)

Pure half `internal/common/timeline.go` (wire types `TimelineEvent/Lane/Data/Line/List/DateReading`, `ParseTimelineDate`, `TimelineTicks`/`TimelineStepFor`, `TimelineWall`/`TimelineFormat`/`TimelineISO`/`TimelineSpanWords`), pinned by `internal/common/timeline_test.go`. Server `timeline.go` (spec, events, list, endpoints, dynamic block `timeline`, export pass) and `timelinesvg.go` (the static picture), pinned by `timeline_test.go`. Endpoints `GET /timeline/events|list|svg|date` from `registerTimelineRoutes` (one line in rest.go). CLI `orgs timeline` (`cmd/oc/commands/orgpkgs/timeline.go`). Nothing is stored: events are found when asked for.

- **Positions are wall-clock fields read as UTC** (`TimelineWall`): `S`/`E` are ms of `time.Date(y,m,d,h,mi,UTC)`, astronomical years (year 0 = 1 BC, Go's and JS's own count). Never an instant (see **Traps: org dates cross the wire as wall-clock fields**). `S`/`E` reach ±8.5e15 (year ±270000) - under 2^53 and inside JS Date's range. **In JS build positions with `pos()`** (`setUTCFullYear`): `Date.UTC(50, …)` is 1950.
- **Historians' years in and out**: `-500` and `500 BC` are 500 BC (astronomical -499); no year 0 in labels. Ticks align on the *historian's* number (`tlLabelYear`/`tlAstroYear`): `…200 BC, 100 BC, 1, 100, 200`, the tick at label 0 drawn at AD 1 - so BC ticks are round numbers and the gap across 1 BC/AD 1 is one year short (invisible).
- **A point's `E` is 0, and 0 is 1970-01-01.** Every "end of an event" must check `Kind != "point"` before reading `E` - the first svg stretched a BC-only timeline to 1970 because `max(S, E)` took the 0 (`TestTimelineSvgTicksAndLabels` caught it via the Today line). Same in worg's `extentOf`.
- **Which date a heading takes** (`timelineDated`, first wins): `:DATE:`, an active range in its own text (`Headline.Timestamps` with `End`), SCHEDULED→later DEADLINE (`planned`), an active timestamp, CLOSED, SCHEDULED, DEADLINE, `:CREATED:`, a datetree day (own title or an ancestor's, `timelineDayRe`). A day-only range's end is the morning after (exclusive); labels print the last day. `clocks:t` adds one span per closed CLOCK line (from `Headline.Clocks`). Eras = a span + `:TIMELINE: era` or tag `:era:`; they get `Lane ""` and are drawn behind every lane. `:TIMELINE: no`/tag `:notimeline:` hides. `:COLOR:`/`:TIMELINE_COLOR:` (palette name via `trackerHues`, or `#hex`) gives `Slot -1`.
- **Scope**: a `#+TIMELINE:` line with no `query:` and no `file:` draws **its own file** (`here`, which the export pass and the dynamic block pass; clients send `here=`). With a query, every file. `file:all` everywhere. `/timeline/events` with nothing at all = every dated heading in every file (on a real GTD tree that is thousands of CLOSED tasks: `limit` 2000 keeps the most recent, `Truncated` says so).
- **Lanes** (`timelineLaneOf`): tag = the heading's **own first tag** as written, then inherited ones (`inheritedTags` sorts, which put `Hadrian's Wall :rome:building:` in `building`); file = `#+TITLE` else base name (own `timelineFileTitle`: `preview.go`'s `fileTitle` vanished mid-session while another agent edited it); parent; keyword; `property:NAME` (own, then ancestors). `auto` = file when several files, else parent when parents differ, else none. Colours = palette slots in order of first appearance (events sorted by time), grey past eight.
- **Options** are `common.ParseTrackerOptions` (the tracker's reader; reads `#+BEGIN:`'s `:key value` too). `from:`/`to:` try `ParseTimelineDate` first (so `-500` is a year, not "500 days ago") then `orgdate.ParseDate` (`-1y`, `today`); `to:` is exclusive at the end of the named period (`Until`). A query with quotes on a line: `query:"HasTags(\"history\")"` (the reader drops unescaped quotes). **There is no `HasTag` query function** - it is `HasTags`; my first examples used `HasTag` and the server answered "Undefined function".
- **The svg** (`timelineSvg`): ink is `currentColor` at strengths (no theme detection; reads on worg's dark html theme, light pages and paper), marks wear the light palette step, today is `#d03b3b`. Labels above their marks, packed per lane (`tlsPack`, at most 6 rows, then marks without labels; widths estimated per character class). Every event is a `<g class="ev" data-i data-hash data-file data-line>` with a `<title>`. Ticks `common.TimelineTicks` at 84px.
- **Export copy** (`timelineExportLines`, in `exportLinesFor` after the tracker pass, only while on): html → `#+BEGIN_EXPORT html` with `<figure class="org-timeline" data-timeline="<options>" data-timeline-file="<file>">` + svg (worg's rendered view makes this live); typst → the svg inline (`image(bytes(…), format: "svg")`, as trackers; not run through typst here); latex/beamer/text/markdown → an org description list `- 14 Oct 1066 :: Battle of Hastings (war)` (no TikZ; a list reads well in print). An unreadable line → `/Timeline: why/` and a stderr line. Lines inside `#+begin_` blocks are skipped.
- **Dynamic block** `#+BEGIN: timeline …` → `#+CAPTION:` + table Date | Event | Lane; Event is `[[id:…][T]]` when the heading has an `:ID:`, `[[*T][T]]` in the same file, `[[file:rel::*T][T]]` otherwise; `|` → `\vert{}`.
- Same-day minute spans print `20 Oct 2026 14:00 – 15:30`.

Twins (for the root list):
- **free dates and the axis**: `common.ParseTimelineDate` ↔ `parseHistDate` in `worg/src/orgtimeline.ts` ↔ `parseHistDate` in `vscode-org-everywhere/src/timeline-model.ts` (a copy of worg's); `common.TimelineTicks` (step ladder, labels, majors, BC alignment) ↔ `timelineTicks` in `orgtimeline.ts`. Same cases in `timelineDateCases`/`timelineTickCases` (`timeline_test.go`), `orgtimeline.test.ts`, `test/timeline-model.test.ts` (dates only). Drift shows as the VS Code hover or worg's *Jump to…* reading a `:DATE:` differently from where the server puts it, or worg's axis ticking differently from the exported picture.
- Cosmetic, not pinned: label packing (`tlsPack` Go ↔ `packLane` TS - the TS one measures real text, so they need not agree), the context band (`contextSpans`, worg only), `TimelineSpanWords` ↔ `spanWords`.

Shared files touched (small): `rest.go` (one route line), `refresh.go` (`tl` flag + pass in `exportLinesFor`).

Tests run: `go test -vet=off ./internal/common/ -run Timeline` and `./internal/app/orgs/ -run TestTimeline` (events, org dates incl. datetree/planned/range/closed, range filter, spec errors, list, html/latex export copy, svg, dynamic block) - pass. Throwaway server on 8122 with three files: svg checked as PNG light and dark; CLI `timeline`, `-file -clocks`, a query, `ls`, `svg -out`, `date`, `-json`, `dblock` on the block - all as expected.

Not done: TikZ for LaTeX (a list instead), a `:DATE_END:`-style second property (ranges go in `:DATE:`), millennia as a `:DATE:` word, decades BC (`1950s` only AD), `IsDated()`-style query function, writing anything (dragging an event to move its date).

### The library: `mediadb.go` (features.mediaDb)

The catalogues are `internal/common/mediadb` (pure; `mediadb_test.go` on saved answers in its `testdata/`): `mediadb.go` (kinds and aliases, `Candidate`/`Item`, `Fields` per kind, `Tags`, `Body`, `CleanText`, shelves `ShelfOf`/`StatusWord`, `ParseRating`, `NormISBN`), `sources.go` (one `Source` per catalogue: openlibrary, googlebooks, tmdb, igdb, rawg, musicbrainz, wikidata, wikipedia; every request through a caller's `Getter`). Server: `internal/app/orgs/mediadb.go` (`registerMediadbRoutes`; `mediadb_test.go` runs the whole thing against an httptest server serving the same fixtures, with `mediaDb.urls` pointed at it). Endpoints `GET /mediadb/search|details|items|sources`, `POST /mediadb/add|refresh|set`; dynamic block `library`. CLI `orgs library` (`cmd/oc/commands/orgpkgs/library.go`). Settings `common.MediaDbSettings` / `MediaDbKind`.

- **A book is a record**: written with `recordHeadingLines` (ID, ADDED, LOGBOOK "Added"), `:RECORD: <kind>`, fields named for records' `fieldOf` (`PUBLISHED_DATE`/`RELEASE_DATE`/`FIRST_AIRED_DATE` are dates by the `_DATE` suffix, `URL` a url, **`IMAGE` not `COVER`** - `COVER` is not in `imageNames`, so it would read as text; reading accepts COVER/POSTER too). Updates (refresh, shelf, stars) go through **`UpdateRecord`** with `Via`. Identity is `MEDIA_ID: source:id` (`openlibrary:OL893414W`, `tmdb:movie/329865`, `wikidata:Q20382729`); duplicates = same MEDIA_ID or same normalised ISBN (`mediadbHaveIndex`), refused unless `Force`, and search hits carry `Have` (the heading's hash).
- **Where a new one goes** (`mediadbTarget`): File/Under asked for → the kind's yaml `file`/`under` → its `capture` template's `CapTarget` → the kind's collection container (`importTarget(kind,…)`) → **`AddCollection`** of `Books`/`Films`/… (icon, `FIELDS`) in `library.org` (made in the first org dir). So the records browser gets a tab per kind for free, and the second film lands in the same collection (tested).
- **Shelves are server-only** (no twin): `STATUS` property (loose words: "watched", "dnf", "on hold"…) → TODO keyword (`keywordInfo`: done = done, CANCELLED = dropped, TODO = want, other active = doing) → FINISHED_DATE/STARTED_DATE → want. `/mediadb/set` writes STATUS (the kind's word) and stamps STARTED_DATE/FINISHED_DATE only when absent. **The keyword is never written** - decided so a `TODO`/`DONE` reading list keeps its keywords; STATUS once written wins.
- **UpdateRecord indents drawer lines by depth**, which made a ragged drawer in a column-zero file (seen live: refresh on a hand-typed heading). `mediadbKeepIndent` re-indents the head's drawer lines to the `:PROPERTIES:` line's indent after every UpdateRecord here (pinned in `TestMediadbRefreshAndDefaultPlace`). records.go itself still has this behaviour for its own form edits.
- **Refresh** (`mediadbRefresh`): MEDIA_ID → details; else ISBN (book) → Open Library; else a title search, preferring a hit with the same title, creator's first name-part and year. Fills only missing fields (`Overwrite` replaces differing ones, never STATUS/RATING), the cover when there is no IMAGE/COVER/POSTER, missing genre tags (`addHeadlineTag`, by row after the update), and the body **only when the heading has no own text and no children** (`UpdateRecord`'s SetNotes replaces to the subtree end, children included).
- **Network** (`mediadbDo`/`mediadbGet`): http(s) only, 15s, 4 MB json / 10 MB covers, User-Agent `orgs/<version> (https://github.com/ihdavids/orgs; <mediaDb.contact>)`, 404 → `mediadb.NotFound` (so a missing Cover Art Archive front is "no cover", silently), GETs cached an hour (cap ~400), **MusicBrainz 1.1s between requests and one retry after 2s on 503** (it answered 503 "busy" during testing, and the album search then fell through to Wikidata with only "nothing found" - the message now lists the sources that failed). Keys go through `hookSecret` (env:/keyring:/literal). IGDB's Twitch token is cached in the pure package until 5 min before expiry.
- **Search** tries the kind's sources in order (`SourcesFor`, yaml `sources:` reorders/limits), skipping one missing a key (`Tried` says "needs mediaDb.keys.tmdb") and passing over errors; first non-empty answer wins. Google Books works keyless but the shared quota was exhausted (429) when tried - hence a hand-written fixture.
- **Source quirks**: Open Library work ids can be **redirect records** (`type /type/redirect`, `location`) - followed once. The work has no authors' names or first year; `search.json?q=key:/works/ID` has both (one request). Edition = `bestEdition` (ISBN, configured language, pages); the work's first cover may be a translation's, so an edition in the configured language wins (Earthsea came back with a Spanish cover before). Wikidata has no type filter in `wbsearchentities`: hits are kept by **their description** (`wdKindRe`/`wdNotRe`: "2016 film by…", "studio album by…", "video game"), creator from "by X". Details: entity claims + one labels request + the Wikipedia REST summary (its lead image is the poster; Commons P18 is often a still or logo - for Breaking Bad it is the logo). Wikidata genre labels end in " film"/" television series" - stripped before tagging. Open Library subjects are noisy: `TagOf` drops anything with `:=,()/[]`, more than 3 words, and a stop list (`accessible_book`, `nyt…`); non-English subjects (`ciencia_ficción`) still get through.
- **Descriptions** (`CleanText`): html tags/entities out, Open Library's `----` trailers, `[text][1]` refs and `([source][1])` dropped, markdown links → org links, paragraphs unwrapped, a paragraph starting `*`, `#+` or `:x:` comma-escaped.
- `Preview` on `/mediadb/add` answers the heading at level 1 with the cover as a url link and writes nothing (CLI `-preview`/`-dry-run`, VS Code's insert-at-cursor).
- **Dynamic block `library`** (`:kind :shelf :sort :limit`): an org table, titles as `[[id:…][Title]]`. Registered in `init()` into `dynGenerators` (dynblock.go untouched).
- Helper names prefixed `mediadb…` (`firstNonEmpty` already existed in assistantcode.go; renamed `mediadbFirst`).
- Not done: IGDB and TMDB were never called live (no keys; fixtures are hand-written from their documented shapes); Google Books likewise (quota). No html-exporter rendering of a cover grid (the dynamic block is the document side); latex/typst nothing special. No query function (`IsRecord("book")` already works).

Twin (for the root list):
- **ISBN normalising** (ISBN-10/13 check digits, hyphens, `ISBN` prefix, 10 → 13): `mediadb.NormISBN` ↔ `normIsbn` in `worg/src/library.ts` (the barcode scanner) ↔ `normIsbn` in `vscode-org-everywhere/src/library-model.ts`; same nine cases in `TestNormISBN`, `library.test.ts`, `test/library-model.test.ts`. Drift shows as a scanned or typed ISBN searched as words.

Shared files touched (small): `rest.go` (one route line), `internal/common/serversettings.go` (the `MediaDb` field + SDOC block, `MediaDbSettings`/`MediaDbKind` types).

Testing live: throwaway server on 8123 (config in the scratch dir, `noAuth`, `accessControl: "*"`, `mediaDb.kinds.book.file`), worg built to scratch with `BUILD_PATH` and served by a same-origin python proxy on 8523; screenshots with puppeteer-core (`tools/screenshots/node_modules`) at 1400 and 400 wide, light and dark. Real catalogue calls worked for Open Library (search, ISBN, work), Wikidata/Wikipedia (film, show, game, other), MusicBrainz + Cover Art Archive.

### Hover previews: `preview.go` (features.hoverEditor)

`internal/app/orgs/preview.go` (`registerPreviewRoutes`; `GET /preview?link=&from=`, `POST /preview/save`), pinned by `preview_test.go`. html half `plugs/html/hoverlink.go` (+ `hoverlink_test.go`). Settings `common.HoverEditorSettings` (`hoverEditor: noWeb, privateHosts, timeout, userAgent`). CLI `orgs peek` (`cmd/oc/commands/orgpkgs/peek.go`). Nothing is stored; nothing new is written into org files.

- **Resolution is transclusion's** (`resolveTransclusion`, `findHeadingRow`, `subtreeRows`, `txAllowed`): id:, `*Title`, `#cid`, `file:x::*H|#cid|42|text`, `./x.org::…`, a whole file (rows after its `#+` header). Added on top: a bare `[[Title]]` is read as `*Title` (org's fuzzy link); http(s) → web card; a `linkProtocols` url → web card of that url, a command → `Kind: command` with `CommandLine` (never run); pictures/pdf/media by extension → `Kind` + `Url` from `resolveOne` (mediaresolve.go), **before** reading lines (a png would otherwise be read as text). Non-org text files are `Kind: source` (not editable); a NUL in the first lines = refused. `/links/resolve` was the brief's suggestion but it only applies `linkProtocols` - not usable for headings.
- **`from`** goes through `previewFrom`: a db file name, an absolute path, else relative to the first org dir (a fragment rendered without a document has no file).
- **Html**: heading kind renders the body without the heading line, planning and property drawer (`txHeadingEnd`), so the card's header is the title; through `htmlExporter().RenderFragmentIn` (plain go-org writer if no html exporter is configured, which is what tests get).
- **Save = row-checked splice** `previewSpliceRows` (shared with `/transclusion/save`, whose `SaveTransclusion` now calls it with an exact-text check). **Base hashes the rows *and the line on either side*** (`previewBase(lines, a, b)`). Hashing only the text failed the test: a save that appends a line to the end of a heading leaves rows a..b reading as before, so a second card still holding the old Base saved over them and left the new line under the next heading. `PreviewSaved` answers the new rows and Base, so a card saves again without a re-read. LinkPreview drops the trailing `""` of `readFileLines` (id: path doesn't) or the EOF neighbour differs from the save's and the last heading of a file can never be saved (test `last heading`).
- **Editable** = org file in the db, not cut short (`previewMaxRows` 400; `::42`/`::text` show 40 rows).

### Quick maths typing: `latexsuite.go` (features.latexSuite, cdlatex, org-fragtog)

The engine, the snippet table format and the maths scanner are `internal/common/latexsuite.go` (pure, `latexsuite_test.go`), with the built-in set `internal/common/latexsnippets.org` embedded (`LatexBuiltinOrg`). In `internal/common` so `orgs latex expand` works with no server. Server: `internal/app/orgs/latexsuite.go` (`registerLatexSuiteRoutes`; `latexsuite_test.go`): `GET /latex/snippets[?builtin=1]`, `POST /latex/snippets/init`, `GET /latex/expand?text=&mode=&tab=&fraction=`, `POST|GET /latex/check`. Settings `common.LatexSuiteSettings` (`latexSuite: snippets, noBuiltin, katex`). CLI `orgs latex snippets|expand|check|init` (`cmd/oc/commands/orgpkgs/latex.go`). html exporter `plugs/html/latexmath.go`.

- **Snippets are org tables.** Every table whose header row has `Trigger` and `Replacement` (optional `Options`, `Description`, `Priority`) is read; the heading above is the `Group`. The user's file is `latexSuite.snippets` (default `latex-snippets.org` under the first org dir), re-read on mtime/size change. Merge (`MergeLatexSnippets`): user rows first; a user row replaces the built-in with the same trigger + mode letters (`tmnMv`); an empty replacement removes it and is not itself a snippet. `/latex/snippets/init` writes a three-row starter (`latexStarter`), **not** a copy of the built-ins (a full copy made every row "yours" in the cheat sheet and froze the defaults).
- **Cell decoding** (`LatexDecodeCell`): `\vert`/`\vert{}` → `|` (org's own table escape; so `\left|` is how a snippet writes one), `\n` not before a letter → newline (so `\nu`, `\neq` survive), `\\` kept, and `=x=`/`~x~` around a whole cell stripped - **but not when the inside is only the mark** (`===` and `~~` are triggers; the first version turned `===` into `=` and every `=` typed in maths became `\equiv`, and `~~` into nothing).
- **Options are Latex Suite's letters** (`t m n M A r w v`); `w` = not straight after a letter or `\` (digits allowed, so `2sin` → `2\sin`). **Tab stops are TextMate's/VS Code's** (`$1`, `${1:x}`, `$0` last), *not* Latex Suite's (its `$0` is the first stop) - so a body goes to VS Code almost as is. Regex captures are Latex Suite's `[[0]]` = first group. Regexes must be RE2 and JS at once (no lookbehind) - the row is dropped (with a `Problems` entry) when Go cannot compile it.
- **Engine rules** (`LatexExpand`): order = priority desc, then longer trigger, then as listed; `A` snippets only as you type, the rest only on TAB; a trigger starting `@` also matches `` ` `` (cdlatex); **in maths nothing expands while a command name is being typed** - if `before` ends in `\letters` and that run starts before the match (`\sq` stays, `\alpha1` still gives `\alpha_1`). This one rule replaces most of Latex Suite's `w`/priority juggling; without it `\text`, `\sqrt`, `\sum` typed out all exploded.
- **`LatexAutoFraction`**: `a/` → `\frac{a}{$1}$0`; the term is letters/digits/`.`/`^`/`_`, `\commands` and balanced `()[]{}` groups backwards; `(a+b)/` loses its brackets; `//` is left to the `//` snippet. Note `1//` does *not* give `\frac{}{}`: the first `/` already made `\frac{1}{}`.
- **The maths scanner** (`LatexFragments`/`LatexModeAt`): `\( \)`, `\[ \]`, `$$ $$`, `$ $` (org's rule: no space after the opener, none before the closer, no letter/digit after it) and `\begin{env}` for maths environments (`LatexMathEnvs`). Unclosed maths runs to the next blank line (maths never crosses one); an unclosed `$` followed by a digit is a price, not maths. `LatexMask` blanks src/example/export/verbatim/comment blocks, `#+` and `# ` lines and `: ` lines first, keeping offsets. Inside maths, an open `\text{`/`\mbox{`/`\operatorname{` group is text mode. The mode scan works on a ±20000-char window round the cursor.
- **`/latex/check`** (`LatexCheck`): braces (`\{ \}` skipped), `\left`/`\right` (`\leftarrow` is not a `\left`), `\begin`/`\end` nesting and names, environments KaTeX/MathJax don't know (`LatexKnownEnvs`, warning), unclosed `\(`/`\[`/`$$`/env (an unclosed `$` is not reported - prices), and `$ x$` (space after the opener: org reads it as text; a warning). `Text` in the body checks an unsaved buffer (VS Code sends it). Col counts runes.
- **html export** (`latexmath.go`, only while the feature is on): each `LatexFragment` becomes `<span class="org-math org-math-inline|display" data-tex="…">` + the maths as typed (no-script fallback); an environment keeps its `\begin…\end` in `data-tex`. `ExportToString` appends `LatexMathLoader()` (KaTeX css + js from `common.LatexKatexBase()`, the `latexSuite.katex` setting, default jsdelivr 0.16.11; `off` = nothing) when the page has a span. **go-org reads `$ 5 and $` as maths** (org does not): the writer writes a `$` fragment with space inside as plain text. latex/beamer/typst untouched (they pass maths through already). Off = byte-for-byte go-org's output (`TestLatexMathInHtml` off half).
- The CDN means an export viewed offline shows the TeX as typed. worg's Files view (an iframe on the export) runs the loader itself; `ThemedHtml` (hover previews, cards - innerHTML, scripts don't run) calls `renderMathIn` from `worg/src/katexload.ts`, MathML-only inside a shadow root (the page's KaTeX css does not reach it).
- **Helper names are prefixed** (`latex…`, `isLatexLetter`, …) - the brief's clash rule.

### org-ql blocks: `orgql.go` (features.orgQl)

Translator `internal/common/orgql.go` (pure, `orgql_test.go`): `OrgQlToQuery(q, now)` reads org-ql's sexp *and* non-sexp syntax into one sexp (`qlNode`), then into the full-form query; `OrgQlColumns`, `OrgQlWords` read `:columns`/`:sort`. Block `dynOrgQl` registered in `init()` into `dynGenerators` (dynblock.go only gained an SDOC paragraph). Test `orgql_test.go` drives `refreshDynBlocks` on a real file (off leaves the file byte-identical and says how to turn it on).

- **Dates go through `PropCompare("DEADLINE", "<=", "<today>")`** (`<-7d>`, `<+7d>`, `<2026-11-05>`), which the query engine already reads; `(closed)` alone is `PropCompare("CLOSED", ">", "<1900-01-01>")` (no CLOSED compares false). `(ts …)` is `HasAnyDate() && !DateBefore(d) && !DateAfter(d)` with OnDate's `"YYYY DD MM"` - only close to org-ql's: it counts planning dates, and a heading with one of its dates outside the span is left out even when another is inside.
- `(priority >= "B")` flips the operator (A is highest, compares lowest).
- Plain syntax: only names in `qlPredNames` are predicates, so `https://x` or `todo` alone are text (MatchContent, `(?i)` unless the word has a capital - org's case-fold). `property:NAME=v` is name and value; `from=/to=/on=/inherit=` are keyword args.
- Unknown predicates (`ancestors`, `parent`, `children`, `outline-path`, `src`, `(clocked :from …)`) are **refused by name** - the block keeps its old rows and the refresh's `Msg` says why.
- Rows: the block's own heading is never one; title cell is `[[id:…]]` when the heading has an ID else `headingLink`; dates via `strftime`, time added when the stamp has one and the format is the default.

Not done: org-ql's `org-ql-search`/views (worg has its own search), `:ts-format` per column, `(clocked)` over a span, ancestors/parent/children predicates (need new query functions), `rifle`'s any-order word matching (each word is its own MatchContent, which is the same thing for AND).
