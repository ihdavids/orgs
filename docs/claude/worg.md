

## More optional packages, second set: map, timeline, library, hover previews, link titles, maths typing, local pictures

Each hides itself while its feature is off (`useFeature`). Server notes: `internal/app/orgs/CLAUDE.md`, the section of the same name.

### Map view: `mapview.go`, `mapgeocode.go`, `mapstatic.go` (features.mapView, org-osm)

- `src/mapview.ts` (types, calls, the twins above, `clusterPins`, `legendOf`, `parseMapLine`/`mapLine`, `tilesFor`, `roundForZoom`, `requestMapHeading`/`onMapHeading`/`takeMapHeading`, `mapFrameUrl`; `mapview.test.ts`), `components/MapView.tsx` (the tab, `PlaceCard`, `PlacingBar`, `MapFrame`, `wireMapFrame`) and `components/MapCanvas.tsx` (Leaflet). Tab key `Map` (App's titles/APPS/switch, `worg:app` params `hash`), sidebar entry gated by `useFeature('mapView')` in AppBar, palette entry in `palette.ts` gated in Palette.tsx.
- **npm dependency: `leaflet` 1.9.4 (+ `@types/leaflet`).** A slippy map with tiles, pan/zoom inertia, attribution control and popups is a library's worth of code; Leaflet is ~40 KB gz with no dependencies. **Lazy**: only `MapCanvas.tsx` imports it (and `leaflet/dist/leaflet.css`), and MapView loads that with `React.lazy`, so the main bundle grows by MapView itself only. No marker-cluster plugin: `clusterPins` (greedy, 42px, centre = mean of members, recomputed on `zoomend moveend`, only pins within the padded view) is 30 lines and tested. The default marker images are not used (divIcon SVG pins), so Leaflet's image-path problem under webpack does not arise.
- **Popups are Joy**: one `L.popup` whose content is a div; React renders `PlaceCard` into it through `createPortal`, so it is inside worg's CssVarsProvider. Leaflet's css gives `<p>` in popups 17px margins - reset in the injected stylesheet (`ensureStyle`, id `worg-map-style`). The popup is offset 28px up so it does not cover the pin.
- **Dark mode**: `mapView.tileDarkUrl` if set, else the light tiles with `filter: invert(1) hue-rotate(180deg) brightness(.92) contrast(.88) saturate(.7)` on `.leaflet-tile-pane` only (pins and popups unfiltered); controls/attribution restyled for dark.
- **Placing**: `placing` state turns map clicks into `onPick` (cursor crosshair) and shows `PlacingBar` over the map: typed coordinates → *Use these*; words → `/map/geocode {Address}` results, hovering one previews a marker, picking writes `Location` = the words as typed plus `Lat/Lon` and `Geo` (checkbox, default on). **A click is rounded to what its zoom can mean** (`roundForZoom`: about a pixel; a click on the world at zoom 2 is `3.9,15.1`, not six decimals).
- **Search → Map**: Search's `RowMenu` has *Show on map* (gated) → `requestMapHeading(hash, title)` + `focusNavigate({app:'Map'})`. A Map tab already mounted gets it through `onMapHeading` (VS Code posting `worg:app` with `params.hash` to an open panel); otherwise it waits, or comes from the url (`?app=Map&hash=` - what WorgPanel puts on its url).
- **Rendered view**: the exporter's `figure.org-map` → `wireMapFrame` (from Files' `onFrameLoad`, feature on) replaces the svg with an `<iframe>` of worg itself in map-only mode: `?mapframe=1&file=&options=&from=&to=&theme=`, which `index.tsx` routes to `MapFrame` instead of `App` (a hook-free branch, so no conditional hooks in App). The frame is same-origin, so the `orgstoken` cookie authenticates it. The theme follows **the page's background** (`pageIsDark`), not worg's - an export theme can be dark in a light worg. *Open* in a frame's card posts `worg:map-open` to `window.top`; Files' listener (`mapUnwire`, one per page load) calls `nav.toFile`. The figure caption list stays; only the picture becomes live.
- Seen in headless Chrome (puppeteer-core from `tools/screenshots`) against the throwaway server, worg built to a scratch folder with `DISABLE_ESLINT_PLUGIN=true` and served through a same-origin python proxy on 8521: the tab light and dark, clusters, the popup card, placing by a click (wrote `:LOCATION:` into the file), the rendered view with the live map. Not tried in a browser: the address search's result list (only via the CLI), *Keep coordinates*, the copy-a-`#+MAP:`-line button, Search's *Show on map*, mobile (the side list is hidden below `md`).

### Timelines: `timeline.go`, `timelinesvg.go` (feature `timeline`)

- `src/orgtimeline.ts` (types, calls `loadTimeline`/`loadTimelines`, `requestTimeline`/`takeWantedTimeline` + `?timeline=&here=&query=`, `pos`/`fields`/`nowPos`, the twins `parseHistDate`/`timelineTicks`, `contextSpans`, `packLane`, `extentOf`, palette `TIMELINE_LIGHT/DARK` + `slotColour`; `orgtimeline.test.ts`). **Not `timeline.ts`**: that name is the D&D session timeline.
- `src/timelineview.ts`: `TimelineView`, the live view in **plain DOM/SVG, no React**, so the same class runs in the tab and inside the Files tab's rendered iframe (whose document React does not own; Joy styles would land in the parent document). It builds SVG strings into three svgs (axis, scrolling body, overview strip) + a hover card div (filled with `textContent`). Renders through rAF, or a 16ms timer when `document.hidden` (rAF never fires in a hidden tab - see memory).
  - **Packing is per zoom, not per pan**: `pack()` lays every event out relative to the `lo` it was packed at (`packLo`, `packScale`) and is redone only when the scale (or width/data) changes; rendering shifts by `(packLo - lo)·scale`. Packing only visible events made rows reshuffle while dragging. Packing uses `right = Infinity` (no flipping labels left) for the same reason.
  - Wheel = zoom about the pointer (ctrl-wheel = trackpad pinch, stronger), horizontal wheel/shift = pan, drag pans time and scrolls lanes, two-pointer pinch, dblclick zoom, keys `+ - ← → t 0`. Clicks are found with `elementFromPoint` on pointerup because the pointer is captured. Zoom clamp 20 min … 2×8.5e15 ms.
  - In `compact` (rendered page): no lane gutter (lane names above lanes), max height then internal scroll, and **the wheel scrolls the page until the view is focused** (or ctrl/pinch) - otherwise a figure in a document traps the page's scroll.
  - Colours: the palette's dark steps on a dark page (`slotColour`), ink/grid/axis per mode from the dataviz chart chrome; the ring under dots is the page surface (`surfaceUnder` walks up for the first opaque background; `isDark` decides the mode inside the iframe, whose html theme may be dark while worg is light).
- `components/Timeline.tsx`: the tab (source picker: every dated heading / each `#+TIMELINE:` line / "as asked"; query; lanes incl. Property…; Clocks; Jump to… with `parseHistDate`; today, zoom, fit, refresh), `TimelineCanvas` (React wrapper; keeps the range when the same question reloads), `wireTimelineFrame` (called from Files' `onFrameLoad` when `featureOn('timeline')`: replaces each `figure.org-timeline` svg with a compact live view from `/timeline/events?line=&here=`, plus "Open in Timeline ↗" → `requestTimeline` + `focusNavigate`). Reloads on `reload` events (shared stream, 400ms debounce). Opening: `nav.toFile` with a Back, or `worg:open` when embedded.
- Gating: AppBar (`TimelineRoundedIcon`, `useFeature('timeline')`), palette.ts PANELS + Palette.tsx `featureOn('timeline')`, the tab's own off state, the frame wiring. App.tsx: import, `APP_TITLES`, `APPS`, switch, and the host `worg:app` params line (`{timeline, here, query}`).
- No npm dependency.
- Seen in headless Chrome (puppeteer-core from `tools/screenshots/node_modules`, worg built to scratch with `TSC_COMPILE_ON_ERROR`/`DISABLE_ESLINT_PLUGIN` because of another agent's `library.ts` type error, same-origin python proxy on 8522 → server 8122): tab light and dark, hover card on a point and a span, wheel zoom + drag on the project timeline, the rendered view's live figure on the dark html theme. Fixed from looking: BC/AD context labels overlapping, a bar's inside label hidden under the gutter when the bar is mostly off screen (now drawn after the bar), lane header text below a one-row lane, tick labels under the Today pill, the right margin on fit. Not tried: touch pinch on a real device, VS Code's webview.

### The library: `mediadb.go` (features.mediaDb)

`src/library.ts` (wire + pure helpers: `normIsbn`, `sortEntries` - "The"/"A" ignored, empties last -, `entryMatches`, `shelfCounts`, `commonTags`, `nextRating` - the same star again clears -, `searchWords`; `library.test.ts`), `components/Library.tsx` (the tab). Mounted as app `Library` (App.tsx import/title/APPS/switch, AppBar entry gated by `useFeature('mediaDb')` with `LocalLibraryRounded`, Palette gate + a `palette.ts` PANELS line).

- Shelves view: kind toggle (only kinds you have, scrollable on a phone), filter, sort, shelf chips with counts, top 8 tag chips; "Everything" shows sections in order In progress, Up next, Done, Set aside. Cover grid `minmax(124px,1fr)`, 2:3 (albums 1:1), titles clamp to two lines, stars on each card editable in place (optimistic, reloads on failure). Serif (Georgia stack) only for shelf headings and dialog titles.
- **Stars are coloured on the icon, not the wrapper**: a `color` on the Box (even a Joy css var) did not reach the MUI icons - they took the text colour (black/white). `STAR = '#f0a92e'` on each icon.
- Search: kind select inside the input, Enter or Search; hits as cover cards (`on your shelf` chip when `Have`; clicking that opens the entry instead). A hit opens `AddDialog`, which loads `/mediadb/details` first (cover, genres, description), then shelf, stars, file/heading (remembered per kind in localStorage) and Add; `Existing` offers Open it / Add anyway. The Item fetched is sent back with the add, so the server does not look it up twice.
- **Barcode**: `BarcodeDetector` (`ean_13`, `ean_8`, `upc_a`) on a `getUserMedia({facingMode: 'environment'})` video, polled every 250ms; the button only shows when both exist (Chrome/Edge Android, Safari 17+). Needs a secure context - over plain http on a LAN address it says so. Not tried on a real phone (no camera in headless Chrome).
- Reloads on the shared `reload` event stream (`openEventStream`), as Recipes does.
- No npm dependency.

### Hover previews: `preview.go` (features.hoverEditor)

`src/hoverpreview.ts` (pure: `orgLinkAt`, `linkFromHref`, `placeCard`, `keepOnScreen`, `whereOf`; server calls `previewOf` (15 s cache) / `savePreview`; the bus `askPreview`/`leavePreview`/`setHoverListener`), tests `src/hoverpreview.test.ts`. `components/HoverLinks.ts` (where previews start), `components/HoverPreview.tsx` (the card host, mounted once in App.tsx beside `NoticeHost`, given `nav`), `components/PreviewEditor.tsx` (lazy; CodeMirror with `analysisField`/`orgHighlight`/`editorTheme` from OrgTextEditor, Mod-S / Mod-Enter save, Esc cancel).

- **One document listener covers every place server html lands** (`wireHoverDocument(document)` from the host): search bodies, kanban card backs, canvas cards, NodeView, agenda popups and the cards themselves, shadow roots included (`composedPath`). It reads `data-org-link`/`data-org-from` spans first, else an `<a href>` turned back into a link (`linkFromHref`: `id:` stays, `x.html` → `file:x.org`, `*Title`; go-org's own writer, used for non-themed bodies, writes no spans). A plain web `<a>` is previewed only inside a card - otherwise every link in the app's chrome would pop a card.
- **Three wirings by hand**: the rendered view's iframe (`wireHoverFrame(frame, selected)` in Files.tsx `onFrameLoad`, offset by the frame's rect - iframe events don't reach the parent); OrgTextEditor (`hoverLinkExtension(filename)` in its extension list; `posAtCoords` + `orgLinkAt`, ignoring positions past a short line's end); the read-only Org view (OrgSource): `sourceHoverHandlers` on a `display: contents` Box around it in Files.tsx, column from `caretRangeFromPoint` against the row's third child (gutter, fold marker, text) and the line from `raw`.
- **Card life**: ask → 400 ms timer (0 with ctrl/meta, or pressing ctrl/meta while resting); leave → 320 ms, then `prune` keeps pinned, editing, under-the-pointer cards and every card those are stacked on (`ask.parent` = the `data-hp-card` the link was in). A new card replaces transient ones that are not its ancestors. mousedown outside closes transient cards; Esc closes the top one (refuses with a note while it has unsaved edits). Editing pins.
- **Placement** (`placeCard`): below the link if it fits, else above, else the larger side with the card shortened; x pulled in from the edges; 8 px margin. A card placed above is anchored by its **bottom** (CSS `bottom`), so a short card still touches the link. Drag/resize clamp with `keepOnScreen` and pin.
- Body styling is the app's (`BODY_SX`, incl. the exporter's `.tags`/`.timestamp` planning spans), not the html theme: a card is part of the app.
- Testing: the Chrome tab runs hidden, so timers are throttled - a real hover's card can appear a second late; `ctrlKey` synthetic events (0 ms) were used to check positions. Seen working on a throwaway server (8124, worg build served by a same-origin python proxy on 8524): rendered view, Org view, editor, a card stacked from a link in a card, edit + ⌘S writing only the heading's rows, the conflict message after an outside edit, light and dark.
- Not seen in the browser (same listener, so expected to work): search result bodies, kanban card backs, canvas cards. Links in those rendered by the plain writer have no `from`, so a `[[*Title]]` there fails ("no heading") unless the server can tell the file.

### Link titles: `linktitle.go` (features.autoLinkTitle, org-cliplink)

- `src/linktitle.ts` (pure rules + the two requests; `linktitle.test.ts`), `components/AutoLinkTitle.ts` (the CodeMirror extension `autoLinkTitle()` and `textareaLinkPaste` for Joy/HTML textareas), `components/LinkTitleButton.tsx` (the dialog). Edits to shared files: `OrgTextEditor.tsx` (two imports, one line in the extensions list - not a compartment: the handler checks `featureOn` itself, so the switch takes effect without reconfiguring - and `<LinkTitleButton buffer>` after `TocMenu`), `Files.tsx` (import + the button beside `TocMenu` when not editing), `Capture.tsx` (`onPaste={textareaLinkPaste}` on the body Textarea; the dialog's outer image paste handler still runs and ignores text), `OrgEditor.tsx` (both body textareas).
- **Undo in the editor** is three transactions so that one undo gives back the plain url: (1) the url, an ordinary `input.paste`; (2) `[[` before and `][Fetching title…]]` after it, `addToHistory: false`; on the answer (3a) those two insertions removed again, `addToHistory: false`, then (3b) `[[` and `][Title]]` inserted, `input.paste` with `isolateHistory.of('before')` (from `@codemirror/commands`, not state). **The url's own characters are never replaced**: if a non-history change replaced the range the paste inserted, the paste's inverse would map to nothing and the second undo would leave the url behind. A url with `[`/`]` (escaped in a link) is therefore pasted plain. Pending placeholders live in a `StateField`, mapped with assoc 1, and are checked against the doc text before (3): an edited placeholder is left alone.
- Shift-paste: a capturing window `keydown` for ctrl/cmd+shift+v arms a 1.5s "plain" flag the next paste consumes (the paste event itself does not say shift).
- **Textareas** go through `document.execCommand('insertText')` when focused, so the browser's own undo has it and React's `onChange` fires; unfocused, `setRangeText` + an `input` event (React's value tracker sees the change since setRangeText bypasses the instance setter).
- The dialog lists one row per url (checkbox, editable title, host + path, "line 3, 9", the failure reason in warning colour); untitled ones can be given a title by typing. Files tab: apply with Hash → on Stale it re-previews. Editor: Text mode, then `setBufferText` (one minimal change).
- Seen in Chrome (scratch build, same-origin proxy on 8525 → server 8125): a paste at the end of a line shows `[[url][Fetching title…]]` and then `[[url][Emacs]]` with the cursor still at the end; cmd+z once gives the plain url, twice removes the paste; a paste over "the manual" gives `[[url][the manual]]` with no request; an unknown host leaves `[[url]]`. The dialog from the Files bar and from the editor bar (buffer changed, not saved) looked right in light mode. Not seen: dark mode, the capture dialog's textarea path, real shift-paste (synthetic paste events only; the keydown flag was not exercised).

### Quick maths typing: `latexsuite.go` (features.latexSuite, cdlatex, org-fragtog)

- `src/latexsuite.ts` (pure engine, test `latexsuite.test.ts`), `src/latexsnippets.json` (built-in copy), `src/latexstore.ts` (the merged set from `/latex/snippets`, asked once and on demand, falling back to the copy; `initLatexSnippets`, `useLatexSnippets`), `src/katexload.ts` (KaTeX: `loadKatex` dynamic-imports `katex` and its css - its own chunk; `renderTex`, `renderMathIn`), `src/latexevents.ts` (the cheat sheet's open event; separate so the palette doesn't pull in the tables), `src/katex-css.d.ts` (types the css `import()`).
- **npm: `katex` added** (^0.16.45, already in node_modules as mermaid's dependency, so no install was needed; `package-lock.json` not touched - run `npm install` once to record it at the root). Needed for the preview, conceal and the cheat sheet; lazy, not in the main bundle.
- `components/LatexSuite.ts` (CodeMirror extension, mounted in `OrgTextEditor` in `latexComp`, **placed before `orgKeys`** in the extensions array so its `Prec.highest` TAB handler runs first; `.org` files only, switched with `useFeature('latexSuite')`):
  - typing: `EditorView.inputHandler` - one typed char; the char is dispatched first as `input.type`, then the expansion with `isolateHistory.of('full')`, so **one undo gives the trigger back**. With a selection, a `v` snippet keyed by the char wraps it.
  - TAB (only when `typing(view)` - vim insert mode): TAB snippet, else next stop, else tabout (`latexTabout`), else falls through to org's TAB. Shift-TAB previous stop; Escape ends the session. `latexTyping` is a module-level alias because the component has its own `typing` const shadowing the function.
  - tab stops: `latexSessionField` (groups of ranges mapped through changes; leaves when the cursor goes outside all of them); a snippet expanded **inside** another's place prepends its groups to the outer's remaining ones (the first version dropped the outer session, so TAB after a nested `ooo` tabbed out instead of moving on). Mirrors (`$1` twice) via a `transactionFilter` that copies the primary range's text into the others (`sequential: true`) - not multiple selections, because `allowMultipleSelections` is off in this editor.
  - preview: `showTooltip` from a StateField that keeps the same tooltip object while the fragment start is the same; the `TooltipView.update` redraws. Below the fragment start (inline) or its end (display).
  - conceal (`latexConceal`, off by default): a StateField of replace decorations for every closed fragment the selection doesn't touch (fragments of the whole doc cached per `Text`; skipped over 2M chars). A StateField, not a ViewPlugin, because replacements cross line breaks.
  - ⌘⌥L opens the cheat sheet.
- `components/LatexSheet.tsx` (mounted in `App.tsx` beside `EditorHelp`; palette entry "Maths snippets" in `Palette.tsx`, gated by `featureOn('latexSuite')`): searchable, grouped, each snippet drawn with KaTeX (stops as `\square`; rows whose stops sit inside `\begin{`/`\text{`, or with `[[n]]`, show code), the four settings (`latexAuto`, `latexFraction`, `latexPreview`, `latexConceal` in `settings.ts`), and *Make my own snippets file*.
- **KaTeX's `throwOnError: false` still throws** for some input (`\cancelto{\square}{x}`: "Expected node of type textord") - an uncaught throw in a React effect blanked the whole page. `renderTex` catches the second render too.
- Seen in Chrome against a throwaway server (scratch build + same-origin proxy): mk/x1/@a/->/a//, //, sr, TAB stops and tabout, sum with placeholders, the preview card, the rendered page drawing inline, display and equation maths. Not seen: dark mode screenshots of the card (theme rules are `&dark`), conceal mode in a long file.

### Local images: `localimages.go` (features.localImages, org-download)

`src/localimages.ts` (requests, `urlKind`, `pastedImageUrl`, `downloadLines`, `sizeText`, `fetchSummary`; `localimages.test.ts`), `src/components/LocalImages.tsx` (everything visible). Files.tsx: `<LocalImagesButton>` next to `<TocMenu>` (not while editing) and `wireLocalImagesFrame(doc, selected, reload)` after `wireDrawingFrame`. OrgTextEditor.tsx: `localImagesPaste(filename)` in the extensions list, right after `citeCompletion`.

- **Dialog**: scan with probe → rows (checkbox, 64×48 thumbnail loaded by the browser straight from the site with `referrerPolicy="no-referrer"`, description or url, `line N · host`, size chip, Skip/failure reason in warning colour; a repeated url is shown but disabled). Run = `/localimages/fetch` with the ticked urls; closes on full success, else re-scans and shows why. "Settings…" expands `LocalImagesSettingsPanel` (folder with `{file}` hint, download on save, `#+DOWNLOADED:` switch; limits/ignore shown read-only).
- **Frame chip**: every `<img>` whose src is `http(s)://` gets a wrapper span, a dashed outline and a hover-only pill "↓ On the web · keep here" (always visible on touch); click = fetch that one url, then reload the frame. Server-served pictures are paths (`/images/…`), so "starts with http" is the whole test (an earlier origin check hid the test pictures because the test host was the page's own origin).
- **Paste composes with autoLinkTitle** (components/AutoLinkTitle.ts, default precedence): mine is `Prec.highest` `domEventHandlers({paste})` and returns false unless the feature is on, the paste is exactly one url whose extension says picture, the selection is empty, ctrl/cmd+shift+v was not just pressed (my own peek-only keydown listener; theirs still sees it), and `titleablePlace` (from their `linktitle.ts`) allows the spot. Extensionless urls go to them (probing first would delay every pasted link). It inserts `[[url][downloading…]]`, then replaces it with `#+DOWNLOADED:` + `[[file:…]]` (line was only the placeholder) or just `[[file:…]]` (mid-line), or `[[url]]` with a warning notice on failure. Seen working in the browser (mid-line case and the failure case; the alone-on-line case only by reading the code).
- Seen in Chrome against a throwaway server (light and dark): dialog, partial run (unticked row left on the web), settings panel, frame chip download. Proxy on 8527 served the scratch build, the test pictures (`/web/*`) and forwarded the api to 8127 - so the "web" host was 127.0.0.1 and needed `allowPrivate: true`.
